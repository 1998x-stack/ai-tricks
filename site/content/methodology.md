# 如何让 A/B 实验给出可信答案

这份手册把技巧当成**待检验的假设**。原文中的“推荐”“必须”“总是有效”不能替代相同条件下的对照。开始训练之前，先把以下内容写清楚。

## 1. 把问题缩小到一个具体操作

“LoRA 有没有用”过于宽泛。可以改成：“同一基座模型、相同数据与训练预算下，rank 从 8 改为 16，对独立任务指标与训练显存有何影响？”

| 协议字段 | 必须说明什么 | 示例 |
|---|---|---|
| 干预变量 | 唯一改变的因素或整体策略 | `adapter.rank` |
| A / B | 具体可执行值 | `8` / `16` |
| 任务 | 真正要解决的问题 | 指令微调，或带独立标签的领域问答 |
| 主指标 | 训练前选定的比较目标 | 任务正确率；不能临时挑有利指标 |
| 额外指标 | 成本、风险与失败模式 | 显存、耗时、格式错误率 |
| 解释范围 | 此次实验不能说明什么 | 小基座结果不代表所有大模型 |

若比较“先调数据再调模型”和“先改架构”，这是整体策略实验。即使只有一个 policy 字段，其内部也可能改变多项配置，不能作单参数因果解释。

## 2. 控制相同的条件

A/B 尽量共享数据版本、样本划分、初始化与数据顺序种子、模型来源、硬件和评测代码。不同结构的参数形状不同，不能声称仅靠相同随机种子就得到完全相同初始化。

多种子实验应保留每一组配对。本站默认种子为 17、42、2026，A/B 顺序交替，减少设备负载、缓存或温度始终偏向一组的影响。种子选择本身不能依赖测试表现。

**配置被接收不等于参数生效。**例如：固定学习率调度不使用 gamma；SGD 不使用 Adam 的 beta2。执行前要验证依赖条件，必要时给两组同时固定同一个调度器或优化器。

## 3. 先锁定数据切分，再开始调参

训练集用于参数学习，验证集用于 checkpoint 和超参数选择，最终测试集用于预先定义的比较。

- 时序问题要防止未来信息进入过去的训练或验证样本。
- 用户、病人、文档等成组数据通常需要按组隔离。
- 文本模板、重复图片和近重复记录可能造成跨切分泄漏。
- 相同数据仓库 revision 不足以证明相同切分；还要记录样本 ID。

本站基础驱动使用固定 Hugging Face revision 与稳定序号切分，并检查 A/B 最终测试 ID 摘要。序号互斥不等于语义去重；真实业务仍要做内容级泄漏检查。

## 4. 明确计算预算的单位

固定 epoch、固定样本数、固定 token 数、固定优化器更新次数和固定 GPU 时间不是同一件事。先选择符合问题的预算单位，再记录其余成本。

| 干预 | 容易混入的因素 | 应额外报告 |
|---|---|---|
| batch 大小 | 参数更新次数、验证频率 | 实际样本数、更新数、验证时点 |
| 梯度累积 | microbatch BN 统计、尾组缩放 | microbatch、有效监督单位、归一化规则 |
| max length | 实际 token、截断内容 | 截断策略、回复保留率、输入长度分布 |
| 模型大小 | 参数量、计算量、预训练差异 | 模型来源、训练成本、初始能力 |
| 搜索方法 | trial 数量和失败试验成本 | 总预算、所有候选与停止规则 |
| 集成、剪枝 | 额外训练及推理成本 | 包括预训练、微调和集成的总成本 |

基础视觉与 SFT 驱动按累计样本数触发验证，尾部只评测一次；不同有效 batch 可能跨过验证阈值，实际触发样本数必须写入日志。预算不足或数据流异常结束应记录失败，不能把部分 epoch 当作完整训练。

## 5. 只按验证集选择 checkpoint

Checkpoint 的选择规则在实验前固定，不能看完测试结果后改用另一个训练步。

改变训练 loss 的实验，仍应使用共同且独立定义的验证目标。例如比较“所有 token 都计算 loss”和“只计算 assistant 回复 loss”时，两组均按回复 NLL 选 checkpoint，否则比较同时混入了不同的选择标准。

最终测试只在选中 checkpoint 后执行。开放对话的 ROUGE-L 衡量参考文本重叠，不能直接代表事实正确性、安全性或人类偏好。任务专用评测要另外实现和登记。

## 6. 保留所有运行证据

一份可审计的结果应包括：

1. 协议、实际配置、代码版本、模型与数据完整 revision。
2. 随机种子、硬件、时间预算、实际样本/token 与参数更新数。
3. 训练/验证曲线及完整原始日志。
4. 最终预测、测试样本 ID 和指标实现。
5. 验证集选中的 checkpoint、选择步数和文件哈希。
6. 失败日志、非有限值和预算耗尽记录。

当前执行器会核对配置回传、checkpoint 哈希、预测文件中的样本 ID，以及完整配对。它不能凭几项 JSON 字段证明一个第三方驱动没有造假；代码审查与原始记录仍然必要。

## 7. 统计差异，不预设胜负

每个种子计算 `delta = B - A`，同时列出两个 arm 的原始值。指标越低越好时，负差值才表示 B 改善；不要只画没有单位的“提升”。

当前汇总按 seed 配对做 bootstrap，并报告均值、标准差和描述区间。三个种子的信息量有限；数百个技巧同时比较还涉及多重比较，不能把偶然的正差值包装为统计显著或普适有效。

负结果、无差异和失败运行都是证据。不要删去不利种子，不要反复调整测试集直到实验“成功”。

## 8. 分清四种完成状态

| 状态 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 协议已写 | A/B 操作、来源、指标明确 | 不表示代码已经实施技巧 |
| 基础驱动配置兼容 | 现有驱动接受这些具体值 | 不表示原文场景已覆盖 |
| 专用场景实现完成 | 模型、数据与指标符合题目 | 不表示真实 GPU 训练通过 |
| 完整训练及复核完成 | 有真实日志、预测与可复核比较 | 仍不能随意外推到其他任务 |

本站目前尚无完成的真实训练结果。查看[实验目录](../../experiments/README.md)了解当前覆盖，查看[驱动契约](../../experiments/DRIVER_CONTRACT.md)了解产物要求。
